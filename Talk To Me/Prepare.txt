------------- Features

[https://docs.realworld.show/implementation-creation/features/]

1. Jwt (login/signup pages + logout button on settings page)
انا مش فاهم قاصده في حتة logout الا هو ازاي استخدم jwt في logout
بس انا الاول محتاج انشا token وابعتها ل user في شكل cokkies
اولا: في حالة sign up
هعمله redirect للصفحه المفروض يخش عليها بعد ما يعمل login
ثانيا: في حالة login
هننشا token عادي وابعتهاله

2. CRU_users (sign up & setting page - no deleting required)
هو انا مش عارف لي مفيش delete بس انا ممكن اضيف الحته دي بس محتاج الاول اعدلها في frontend ولما user يعمل delete هأقله يدخل كلمة السر علشان أتاكد انه هو ولا لا + هقله ان الحساب هيتمسح بعد 30 يوم مثلا.

3. CRUD Articles
دي مفهومه

4. CR-D comments on articles (no updating required)
مفيش update او edit غريبه بس انا محتاج اضيف edit علي الكومينتس

5. Get and display paginated list of articles
مفهومه

6. favorite articles
محتاج اهندل حاجتين لما user يضيف favorite article ولما يعوز يشوف favorite articles بتاعته.

7. follow other users
مفهومه

هو دلوقتي في entity ل user, article, comment, favorite article, followers and following
مش عارف انا صح ولا بس مع قراءة documentation اكتر هنفهم اكتر
------------- End of the features

1. Authentication
POST /api/users/login
Request Filed { email, password }

Reuest Body
{
  "user":{
    "email": "jake@jake.jake",
    "password": "jakejake"
  }
}
هسنخدم username, email علشان انشا token for the user
Response Body
{
  "user": {
    "email": "jake@jake.jake",
    "token": "jwt.token.here",
    "username": "jake",
    "bio": null,
    "image": null
  }
}
هو مفيش authorization
طب لو هعمل authorization المفروض اعملها علي اي ؟ معنديش فكره الصراحه
لما نتعمق شويه هشوف هل ممكن اعمل authorization ولا لا.

10. Get Article (no authentication required)
GET /api/articles/:slug

slug
هو مشتق من title ولكن مع بعض التعديلات مثل اضافة هذه العلامات - لكي يبقي unique
ماذا لو هنالك مقال يحملان نفس العنوان كيف يتم تحديد هذه العلامات مش منطقي هروح ابحث في database عن هذا ال title اذا كان موجود ولا لا اكيد هنالك طريقة اخري للتعامل مع هذا الامر وسوف ابحث عنها حين اصل الي هنا.
لما لا نستخدم id الخاص ب article
محركات البحث تبحث عن كلمات مفتاحيه لذلك لابد من وجود هذا slug للتحسين من الموقع وابجاد المستخدم له بسهوله.

---- Cors
[https://docs.realworld.show/specifications/backend/cors/#considerations-for-your-backend-with-cors]

ما هو cors
هو اختصار cross-origin resource sharing
لا اعرف ما فائدته ولكن دعنا نبحث ونقرأ عنه
cors is a browser security mechanism
في الطبيعي لو عملت fetch for api في frontend لو السيرفر في response headear مفيش
Access-Control-Allow-Origin: https://your-site.com
المتصفح بيمنع ان fetch دا يحصل.

لا تنسي ان تضع cors in code (origin, method, headears)

---- End of Cors


---- Error Handling

Errors and Status Codes
If a request fails any validations, expect a 422 and errors in the following format:

{
  "errors":{
    "body": [
      "can't be empty"
    ]
  }
}

Other status codes:
401 for Unauthorized requests, when a request requires authentication but it isn’t provided

403 for Forbidden requests, when a request may be valid but the user doesn’t have permissions to perform the action

404 for Not found requests, when a resource can’t be found to fulfill the request
